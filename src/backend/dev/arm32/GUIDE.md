# ARM32 Dev Backend Guide

How the arm32 dev backend is put together today, and how to test each part by
hand and with the tools. `DESIGN.md` (this directory) explains the decisions;
`TOOLS.md` documents each tool in detail; the plan is
`projects/big/arm32-dev-backend.md`; defects found along the way are in
`projects/big/arm32-dev-backend-issues.md`; every change to pre-existing code
and its reason is in `projects/big/arm32-dev-backend-existing-code-changes.md`.

## What works today

- The A32 encoder produces the exact bytes LLVM's assembler produces for every
  instruction it supports (integer, branch, load/store, VFP).
- `ElfWriter` writes arm32 objects as ELF32 with REL relocations that LLD
  links; a hand-built function runs under `qemu-arm`.
- The arm32 runtime objects (builtins, compiler-rt, default platform, Boxy
  runtime) build for `arm32musl` and `arm32glibc`, and the test platforms
  declare `arm32musl`.
- The shared driver (`LirCodeGen`) refuses to compile for arm32 at every
  architecture decision it has not been taught, and is partway through
  separating pointer-sized words from genuine 64-bit values (A2).

What does not work yet: there is no arm32 `CodeGen`, so `roc build --opt=dev
--target=arm32musl` stops with "The native object backend does not support the
'arm' architecture". That refusal is removed in J2, after J1 writes the code
generator.

## How the pieces fit

```
Roc source -> checked modules -> LIR (usize = u32 for arm32)
   -> LirCodeGen (src/backend/dev/LirCodeGen.zig)           shared driver
        -> CodeGen (per ISA; arm32/CodeGen.zig is J1)        instruction selection
             -> arm32.Emit (arm32/Emit.zig)                  A32 encodings
   -> ObjectWriter -> ElfWriter.write32 (object/elf.zig)     ELF32 + REL
   -> ld.lld (via the CLI) + the arm32 runtime objects       executable
```

### The encoder: `arm32/`

- `Registers.zig`: `GeneralReg` r0-r15 (`fp`/`ip`/`sp`/`lr`/`pc` are
  declarations) and the VFP/NEON bank as `SReg`/`DReg`/`QReg` views of one file.
  `FloatReg` is `DReg`, the unit an allocator owns; `sLow`/`sHigh`/`dLow`
  convert between views.
- `Emit.zig`: one function per instruction form. Immediates are typed: a
  data-processing immediate is a `ModImm`, which only exists for encodable
  values; memory offsets are checked against `fitsImmediate(form, offset)`.
  Branch offsets are relative to the branch; the encoder applies A32's PC+8
  bias. The `CC` namespace holds the AAPCS32 register roles.
- `Call.zig`: AAPCS32 register sets and allocation masks.
- `encoding_oracle_tests.zig`: generated byte-exact tests (never edit by hand).

### Architecture dispatch: `src/backend/dev/isa.zig`

`Isa = { x86_64, aarch64, arm32 }` and `isaOf(target)`. In `LirCodeGen`,
`FrameBuilder` and `CallingConvention`, every architecture decision is either
an exhaustive `switch (isa)` or `isa.binaryIs(.x)`, which is a compile error
for arm32. The count of `binaryIs` sites (`grep -c binaryIs
src/backend/dev/LirCodeGen.zig`) is the size of J1's remaining checklist.

### The per-ISA seam: `CodeGen` and `CC`

Each ISA's `CodeGen` (`x86_64/CodeGen.zig`, `aarch64/CodeGen.zig`) owns the
temporary register allocator (`allocTempGeneral`/`allocTempFloat`, which record
`general_high_water`/`float_high_water`), the CPU level, and the ISA-neutral
helper methods the driver calls (`emitLoadStackW8`, `emitSetCond`,
`condEqual`, ...). Each `Emit(target).CC` names the register roles
(`BASE_PTR`, `ROC_RET_REGS`, `RESULT_PTR_SAVE_REG`, `WORD`, ...). arm32 plugs
in by providing its own `CodeGen` and `CC` with the same names.

### The width vocabulary (A2)

Inside `LirCodeGen`: `word` (register width of a usize value), `word_size`,
`listFieldOffset("length")`, `strFieldOffset("length")`, `wordOffset(i)`,
`word_sign_bit`, `small_str_len_shift`, `erased_layout` (erased-callable
layouts for the target word), and `wordAsU64` (a usize result Roc types as
`U64`). All of them equal today's constants on 64-bit targets. A remaining
`.w64` in the driver is a site not yet classified; arm32's `RegisterWidth` has
no `w64`, so each is a compile error for arm32.

### Objects: `object/elf.zig`, `Relocation.zig`, `Dwarf.zig`

`ElfWriter.write` dispatches to `write64` (x86_64/aarch64, unchanged) or
`write32` (arm). `write32` emits `Elf32_Rel` records and stores each
relocation's addend into its field (REL form); it adds `.ARM.attributes` and a
`$a` mapping symbol. The arm relocation kinds are `DataRelocationKind.abs32`,
`.arm_movw_prel`, `.arm_movt_prel` plus `R_ARM_CALL` for calls.

### Runtime artifacts

`build.zig` builds six objects per arm32 target into
`src/cli/targets/arm32{musl,glibc}/`; the CLI embeds them
(`src/cli/main.zig`, explicit arm32 rows). `src/default_platform/linux_runtime.zig`
has the A32 `_start`. `test/fx` and `test/int` declare `arm32musl` with
vendored musl `crt1.o`/`libc.a`.

## Testing each part

Set `TMPDIR` to a writable directory for the snapshot tool (it refuses to run
without one). `zig build` steps rebuild what they need; direct binaries under
`zig-out/bin/` are faster when iterating.

### Encoder

With the tool (preferred):

```
python3 ci/arm32_encoding_oracle.py          # regenerate the tests after adding entries
python3 ci/arm32_encoding_oracle.py --check  # what CI runs (run-check-arm32-encoding-oracle)
zig test --dep roc_target -Mroot=src/backend/dev/arm32/mod.zig -Mroc_target=src/target/mod.zig
```

The last command runs the arm32 module's tests alone in seconds (184 today).
To add an instruction: add the emitter to `Emit.zig`, add one or more lines to
`ci/arm32_encoding_oracle.s`, regenerate, run the tests. The oracle refuses to
pass while an emitter has no entry.

By hand, to see what LLVM produces for an instruction:

```
printf '.syntax unified\n.arch armv7-a\n.fpu neon-vfpv3\n.arm\nvadd.f64 d0, d17, d31\n' > t.s
zig cc -target arm-linux-musleabihf -c t.s -o t.o
llvm-objdump -d t.o                    # or: zig objcopy -O binary --only-section=.text t.o t.bin && xxd t.bin
```

### Registers, calling-convention constants, relocation patchers, DWARF

Unit tests inside the backend module:

```
zig build run-test-zig-module-backend
```

That step currently reports failure even when every test passes, because one
wasm test writes to stderr (see the issues note). Run the binary directly to
see the real result: `$(ls -t .zig-cache/o/*/backend | head -1)` ends with
"N passed; 1 skipped; 0 failed."

### The 64-bit targets did not change (every Track A step)

```
zig build build-snapshot-tool build-test-eval-runner
for f in test/snapshots/dev_object_*.md; do ./zig-out/bin/snapshot --check-expected "$f"; done
./zig-out/bin/eval-test-runner --check-dev-code-hashes test/dev_code_hashes/eval.blake3
```

(`zig build run-check-snapshots` and `zig build run-check-dev-code-hashes` are
the same checks as build steps; the second is in minici.) Any mismatch in a
Track A change is a bug. For an intended codegen change, regenerate with
`./zig-out/bin/snapshot --update-expected <file>` and `--write-dev-code-hashes`,
and review the diff.

These hashes do not depend on the compiler's git revision (procedure symbol
names are canonicalized). To confirm that by hand, temporarily replace
`getCompilerVersionGit(b)` in `build.zig` with a fixed string, rebuild both
tools, rerun both checks (they must still pass), and restore `build.zig`.

### Objects and the link

```
python3 ci/arm32_link_smoke.py            # encoder + ELF32 + LLD + qemu (needs qemu-arm-static)
python3 ci/arm32_link_smoke.py --no-run   # without qemu
python3 ci/arm32_link_smoke.py --keep out # keep the .o and executable
```

By hand, on any arm32 object:

```
python3 ci/elf32_reader.py --header --attributes --sections --symbols file.o
readelf -h -A -r file.o                   # Linux cross-check
llvm-objdump -d -r file.o
```

### Runtime objects and the CPU floor

```
zig build roc                             # builds src/cli/targets/arm32{musl,glibc}/*.o
for f in src/cli/targets/arm32musl/*.o; do python3 ci/elf32_reader.py --header --attributes "$f"; done
zig build run-test-zig-module-roc_target  # includes the test pinning Zig's arm baseline to the D2 floor
```

Each object must print `Class: ELF32`, `Machine: ARM`, `Flags: 0x5000400`,
`Tag_CPU_arch: 10` and `Tag_ABI_VFP_args: 1`.

### The CLI end to end

```
./zig-out/bin/roc build --opt=dev --target=arm32musl test/fx/hello_world.roc
```

Today this prints "The native object backend does not support the 'arm'
architecture" (expected until J2). `roc build --target=arm32musl` without
`--opt=dev` uses LLVM and keeps its 64-bit-only diagnostic by design.

### Register budget

`general_high_water` and `float_high_water` on each `CodeGen` hold the most
registers in use at once. To measure over a corpus, read them after compiling
(the A1 measurement did this with temporary instrumentation in the eval
runner's hash mode; the numbers are in `DESIGN.md`).
