# Step 2: registers and the A32 encoder

## Goal

Every arm32 instruction the backend uses is encoded correctly, as checked
byte for byte against the GNU assembler.

## Files from the reference snapshot

- `src/backend/dev/arm32/Registers.zig`: core registers r0 to r15, and the
  S, D and Q views of the VFP and NEON registers.
- `src/backend/dev/arm32/Emit.zig`: the encoder, about 2,000 lines and
  165 public functions.
- `src/backend/dev/arm32/encoding_oracle_tests.zig`: generated by the
  oracle.
- `ci/arm32_encoding_oracle.s`: one line per instruction form.

## Mirrors

`src/backend/dev/aarch64/Emit.zig` and `aarch64/Registers.zig`. What
differs on arm32:
- every instruction has a condition field
- immediates are an 8-bit value rotated right by an even amount, not a
  12-bit field
- the PC reads as the instruction's address plus 8
- S and D register numbers split across two fields
- 64-bit integer products come back in two registers

## Holes

Exactly the thirteen from `LEARNING_HOLES.md`, stage 1:

| Hole | Function | The concept |
|---|---|---|
| 2.1 | `ModImm.encode` | an 8-bit value rotated right by an even amount |
| 2.2 | `dataProc` | the one layout behind add, sub, and, cmp and mov |
| 2.3a, 2.3b | `encodeMovwMovt`, `movRegImm32` | loading any 32-bit constant |
| 2.4 | `multiply` | mul, and a 64-bit product in two registers (umull) |
| 2.5 | `encodeBranch` | PC-relative offsets, and why 8 is subtracted |
| 2.6 | `loadStoreWordByte` | base plus offset, the up/down bit |
| 2.7a, 2.7b | `push`, `pop` | register lists as bit masks |
| 2.8a, 2.8b | `vfpDataProc`, `vfpLoadStore` | how S and D register numbers split |
| 2.9 | `neonThreeSameFields` | one NEON family |

Before the holes: the blank-page exercise from the holes plan (the bytes of
`mov r0, r1`, `add r0, r1, #4`, `ldr r0, [r1, #8]`, `bl`, `bx lr`, written
without the reference). The ARMv7-A manual is the source. Each stub panics
with its hole number, and its bit-layout comment is removed.

`ModImm.encode` is also used at compile time. Its stub keeps a slow search
over all 4,096 encodings so the branch compiles, and panics at run time
until the hole is filled.

## Check

```sh
python3 ci/arm32_encoding_oracle.py --check
zig test --dep roc_target -Mroot=src/backend/dev/arm32/encoding_oracle_tests.zig -Mroc_target=src/target/mod.zig
```

The second command runs every encoder test in seconds. Each crash names its
hole. To compare with the reference after a hole:
`git diff 2f5d8e3685 -- src/backend/dev/arm32/Emit.zig`.

Test counts: to be measured. On the holes branch, with every hole open,
669 passed and 198 crashed, and with all filled, 867 passed.
